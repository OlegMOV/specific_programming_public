1. Встановлення та основи роботи з фреймворком Scrapy

Теорія - 10 хв, практика - 10 хв

🎯 Фреймворк - це програмна інфраструктура, що складається з набору готових інструментів, бібліотек, шаблонів та правил для спрощення й прискорення розробки складних програмних продуктів.

🎯 Scrapy - це фреймворк для добування структурованих даних із веб-сторінок.

Містить у собі інструменти щодо завантаження веб-сторінок та доступу до її елементів з використанням бібліотек BeautifulSoup, Selectolax.

Зазвичай, для початку роботи із фреймворком створюють віртуальне середовище де встановлюють необхідні залежності для роботи даного фреймворка.

Рис. 1.1

Після встановлення, для початку роботи створюється окремий проект

scrapy startproject name_project

Дана команда створює базову структуру проекту. У подальшому для роботи необхідно визначитися із електронним ресурсом, інформація із якого потребує завантаження.
З використанням командного рядку створюється файл для роботи із електронним джерелом

cd name_project

scrapy genspider name_spider source_domen

У даному коді здійснено перехід у теку створеного проекту, і, перейшовши, створення файлу для реалізації парсингу визначеного електронного ресурсу

  • genspider - команда для фреймворка щодо генерування файлу для парсингу;
  • name_spider - назва файлу для відповідного електронного джерела (сайту);
  • source_domen - домен де розміщений ресурс, наприклад для вікіпедії - 'wikipedia.org'

🎯 Spider (павук) при парсингу — це програма, яка систематично переглядає веб-сторінки, переходячи за посиланнями, щоб зібрати контент, проаналізувати структуру сайту або знайти конкретні дані.

Виконавши команди з'являється у проекті файлова структура, яка є основою для подальшої розробки

name_project/
└── name_project/

	│
    ├── middlewares.py    # project middlewares file
	│
    ├── pipelines.py      # project pipelines file
	│
    └── settings.py       # project settings file

2. Аналіз структури електронного ресурсу у браузері

Теорія - 10 хв, практика - 20 хв

Перш ніж писати код, потрібно зрозуміти, що веб-сторінка — це не просто текст, а ієрархічна структура, яка називається DOM (Document Object Model).

  • Теги: Визначають тип даних (<div>, <a>, <h1>, <table>).
  • Атрибути: Додаткові властивості (class, id, href, src).
  • Вкладеність: Елементи знаходяться всередині інших, утворюючи відносини «батько-дитина».

Інструменти розробника (DevTools) - це головний «ніж» парсера. Щоб відкрити їх, натисніть F12 або Ctrl+Shift+I у будь-якому сучасному браузері.

🔑 Ключові вкладки для парсингу:
  1. Elements: Дозволяє переглядати HTML-код, змінювати його «на льоту» та копіювати селектори.
  2. Network: Показує, звідки приходять дані. Якщо контент завантажується динамічно (через API), його краще перехоплювати тут.
  3. Console: Ідеальне місце для тестування селекторів за допомогою JavaScript команди document.querySelectorAll('ваш_селектор').

🎯 Селектори — це адреса даних. Якщо ви помилитеся в адресі, парсер принесе порожній результат.

🔑 CSS-селектори (найчастотніші)
Тип Синтаксис Приклад
Тег назва_тегу h1 (всі заголовки)
Клас .назва_класу .price (ціна товару)
ID #id_елемента #main-content (унікальний блок)
Атрибут [атрибут] a[href] (всі посилання)
Комбінація div.product > span span всередині div з класом product

Для складних випадків застосовують мову запитів XPath
XPath дозволяє рухатися не тільки вниз по дереву, а й вгору або шукати елементи за текстом.

  • //div[@class="title"] — знайти всі div з класом title.
  • //a[contains(text(), "Купити")] — знайти посилання з конкретним текстом.
📌 Алгоритм дослідження сторінки перед парсингом
  1. Інспектування: Натисніть правою кнопкою миші на потрібний елемент (наприклад, ціну) -> "Переглянути код" (Inspect).
  2. Пошук закономірностей: Подивіться, чи мають схожі елементи (всі товари в списку) однаковий клас.
  3. Перевірка на унікальність: Натисніть Ctrl + F у вкладці Elements і введіть свій селектор. Подивіться, скільки елементів він знаходить.
  4. Аналіз динаміки: Оновіть сторінку. Якщо дані зникають до повного завантаження або з'являються через секунду — вам знадобиться інструмент, що підтримує рендеринг JS (наприклад, Selenium або Playwright).
Потрібно уникати селекторів, які генеруються автоматично (наприклад, .css-19vdf0s). Вони змінюються при кожному оновленні сайту. Шукайте змістовні назви класів.

Щоб скористатися селекторами по вибору потрібної інформації на сторінці, на початковому етапі є можливість скористатися інструментами для розробника у браузері

Рис. 1.3

Щоб перевірити CSS селектор є можливість використати об'єкт document та його метод .querySelectorAll('table').

Об’єкт document – це головна “точка входу” до сторінки. Застосовуючи його є можливість змінити або створити що-небудь на сторінці.

Аргументом даного методу є текстовий рядок у якому є можливість тестувати комбінацію селекторів для обрання елементів / блоків на сторінці, що містять необхідні дані.

Для запуску парсера необхідно перейти у теку з проектом

cd name_project

та запустити відповідний парсер

scrapy crawl ter_communities_zt
Для запуску бажаного парсера використовується значення атрибуту name, створеного фреймворком класу

У консолі виводиться обраний блок html-тегів. Тому подальші дії направлені на деталізацію селекторів для вибору конкретної інформації.

Для прикладу отримаємо список назв громад та їх адміністративних центрів

def parse(self, response):
        table = response.css('table')[1];
        for row in table.css('tr'):
            yield {
                "name_communities": row.css('td:nth-child(1) a::text').get(),
                "main_town": row.css('td:nth-child(4) a::text').get()
            }
У функції парсера замість службового слова return використовується yield для оптимізації роботи

У консолі, поряд зі службовою інформацією, виведено рядки із відповідними об'єктами, що містять інформацію за отриманим запитом.

Щоб отримати дані у файл, достатньо у командному рядку дописати атрибути

scrapy crawl ter_communities_zt -o name_file.csv
Атрибут -o (output) говорить про те, що виведення буде здійснюватися у файл name_file.csv без перезапису його у майбутньому. Для перезапису - модифікатор -o потрібно записати у верхньому регістрі -O

Файли для збереження можуть бути різних типів: json, xml, html etc.

4. Налаштування фреймворку для роботи із складними проєктами

Теорія - 20 хв, практика - 30 хв

Розглянутий підхід дозволяє вирішувати завдання щодо отримання інформації із веб-сторінки. Але при більш складних завданнях Scrapy дозволяє систематизувати код для реалізації парсера.

Для більш гнучкого налаштування полів даних, які отримуються у ході парсингу, у структурі проекту є відповідний файл items.py. 

# items.py
import scrapy

class CommunityZtItem(scrapy.Item):
    name_communities = scrapy.Field()
    main_town = scrapy.Field()

І відповідно код парсера також змінюється

import scrapy
from sp_06__scrapy.items import CommunityZtItem

class TerCommunitiesZtSpider(scrapy.Spider):
    name = "ter_communities_zt"
    allowed_domains = ["wikipedia.org"]
    start_urls = ["https://uk.wikipedia.org/wiki/Список_територіальних_громад_Житомирської_області"]
    
    def parse(self, response):
        table = response.css('table')[1]
        for row in table.css('tbody tr'):
            item = CommunityZtItem()
            item['name_communities'] = row.css('td:nth-child(1) a::text').get()
            item['main_town'] = row.css('td:nth-child(4) a::text').get()
            yield item

Після запуску видно, що дані з ресурсу отримані такими ж. Але тепер код рознесений у різних файлах, де можна відповідно застосовувати різні покращення.

Відповідно файл items.py містить змінні, які є екземплярами класу scrapy.Field(). Це дозволяє до даних застосовувати різні методи, які є реалізовані у фреймворку.

import scrapy
from itemloaders.processors import TakeFirst, MapCompose
from w3lib.html import remove_tags

class CommunityZtItem(scrapy.Item):
    name_communities = scrapy.Field(
        input_processor=MapCompose(remove_tags, str.strip),
        output_processor=TakeFirst()
    )
    main_town = scrapy.Field(
        input_processor=MapCompose(remove_tags, str.strip),
        output_processor=TakeFirst()
    )

У даному прикладі застосована два методи: видалення тегів із отриманого рядку та видалення пробільних знаків на початку та вкінці рядка

<div> <span>  Hello world  </span> </div> --> remove_tags --> "  Hello world  "
<span>  Hello world  </span> --> str.strip  --> "Hello world"

Результат при виведенні даних у файл залишається таким же.

Для впорядкування використання селекторів у парсері застосовують клас ItemLoader


from scrapy.loader import ItemLoader

class ...
	....
	def parse(self, response):
		for row in response.xpath('//table[2]/tbody/tr'):
	        item = ItemLoader(item=CommunityZtItem(), selector=row)
	        item.add_css('name_communities', 'td:nth-child(1) a')
	        item.add_css('main_town', 'td:nth-child(4) a')
	        yield item.load_item()

Аргументами для даного екземпляру класу є item=CommunityZtItem(), що дозволяє роботу із полями, а також selector=row - рядок із документу, який є джерелом для роботи на основі доданих селекторів item.add_css(...).

Також показано варіант роботи з xpath - альтернативою для css-селекторів. Так код запиту є коротшим.

При передачі селекторів у item.add_css(...) у кінці не передається a::text, оскільки метод remove_tags у файлі items.py дозволяє уникнути такої необхідності, видаляючи примусово із рядка теги.
