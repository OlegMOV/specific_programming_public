1. Парсинг сайту, суть та підходи

Теорія - 20 хв, практика - 0 хв

У ході реалізації процесів прийняття рішень важливим етапом є оцінювання обстановки, що склалася. Зазвичай для цього здійснюється збір усієї доступної інформації, яка може безпосередньо або опосередковано містити необхідні дані. З огляду на сьогодення, переважна більшість подій знаходять своє відображення, з різним ступенем упередженості, у електронному інформаційному просторі.
Очевидним підходом є агрегування такої інформації з подальшим її аналізом. Проблемним питанням при цьому є відвідування великої кількості інформаційних джерел та об'єми даних, які необхідно опрацювати.
Автоматизація такої ідеї називають запозиченим словом парсинг даних.

🎯 Парсинг — це процес автоматичного збору, аналізу та структурування даних із різних джерел (веб-сторінок, файлів, баз даних), що реалізується на основі відповідних програмних додатків.

До переваг автоматизації такого процесу слід віднести:

  • швидкий доступ до інформації
  • регулярність оновлення інформації та безперервність такого процесу
  • виключення помилок оператора
  • впорядкованість отриманих даних
  • можливість доступу до ретроспективних даних

Процес зазвичай складається з трьох основних етапів:

Рис. 1.1

Розроблена програма надсилає HTTP-запит на сервер сайту. Сервер, отримавши запит, повертає HTML-код сторінки (або JSON-дані). Програма проводить пошук потрібних елементів у коді за допомогою селекторів і зберігає їх у зручному форматі (CSV, JSON, Excel).
Як правило, електронні сторінки (HTML-код сторінки) містять багато іншої інформації, яка не стосується тематики пошукового запиту. З огляду на це необхідно уточнювати пошук у ході видобування даних. Для цього є різні підходи:

  • CSS Selectors - шлях до елемента через його класи або ID (наприклад, .news-item, #main-field).
  • XPath - більш гнучка мова запитів, яка дозволяє здійснювати навігацію по ієрархії DOM-дерева (наприклад, //div[@id='content']/h1).
  • Regex (Регулярні вирази) - для пошуку специфічних шаблонів тексту (email, номери телефонів).

Оскільки тематика не є новою то існує достатня кількість бібліотек, що допомагають реалізувати такий функціонал.

  • BeautifulSoup - парсинг статичних HTML-сторінок;
  • Scrapy - фреймворк для масштабних проєктів (багатопотоковість, обробка помилок);
  • Selenium / Playwright - для динамічних сайтів, де контент завантажується через JavaScript (імітація дій реального користувача в браузері).

Важливо дотримуватися правил «цифрового етикету»:

Що можна робити ✅ Чого варто уникати ❌
Читати файл robots.txt (там вказані дозволи). DDOS-ити сервер (занадто часті запити).
Парсити відкриті публічні дані. Красти інтелектуальну власність або персональні дані.
Використовувати API сайту, якщо воно доступне. Обходити платіжні шлюзи або закриті зони.

Завдання з парсингу даних можна класифікувати за кількома ознаками:

  • залежно від технології, що використовується;
  • об’єкта, що є джерелом інфорфмації;
  • спосіб взаємодії з сайтом.

1.1. Технологія реалізації

Статичний парсинг (HTML Parsing)

Це збір даних із серверних відповідей, які вже містять весь текст у HTML-коді.

  • Як працює: Програма завантажує код сторінки та шукає теги.
  • Інструменти: Python (BeautifulSoup, lxml), PHP (Simple HTML DOM).
  • Плюси: Дуже швидкий, споживає мінімум ресурсів.
  • Мінуси: Не працює з сайтами, де контент з'являється після завантаження (наприклад, нескінченна стрічка новин).
Динамічний парсинг (Browser Automation)

Використовується для сайтів на сучасних фреймворках (React, Angular, Vue), де дані підвантажуються через JavaScript.

  • Як працює: Програма запускає реальний браузер (або його копію), чекає виконання скриптів і тільки потім забирає дані.
  • Інструменти: Selenium, Playwright, Puppeteer.
  • Плюси: Дозволяє імітувати кліки, прокрутку та заповнення форм.
  • Мінуси: Потребує багато оперативної пам'яті та працює повільніше.

1.2. Метод доступу до даних

Парсинг через API

Багато великих сервісів (Google, YouTube, Twitter, маркетплейси) мають офіційні інтерфейси для розробників.

  • Особливість: Ви отримуєте дані у структурованому форматі (JSON/XML) за прямим запитом.
  • Переваги: Це легально, надійно і дані ніколи не "з'їдуть" через зміну дизайну сайту.
Прямий веб-скрейпінг (DOM Parsing)

Збір даних безпосередньо з візуальної частини сайту. Це саме те, що ми називаємо "класичним парсингом", коли скрипт витягує інформацію з тегів <div>, <span>, <table>.

1.3. Спосіб взаємодії із сайтом

  • Односторінковий - збір даних із однієї сторінки;
  • Глибинний (Crawling) - алгоритм передбачає перехід за посиланнями всередині сайту;
  • Наскрізний - пошук специфічних даних на різних доменах.

У даній дисципліні будемо розглядати парсинг як роботу із веб-ресурсами, які містять веб-сторінки (html-сторінки).

2. Бібліотека requests

Теорія - 10 хв, практика - 30 хв

Інформація є продуктом, що має свою комерційну цінність, а тому певні електронні джерела обмежують доступ до своїх ресурсів. Такі обмеження можуть реалізовуватися на основі заборони програмного завантаження інформації, наприклад із використанням бібліотеки requests. На сайтах для цього застосовуються програмні рішення, що реалізують логіку щодо виявлення ознак та визначення роботизованих клієнтів та реальних користувачів.

Для актуалізації інформації щодо застосування бібліотеки requests, виконати наступне завдання.

Розглянемо приклад отримання відкритих даних із сайту Верховної Ради України про “Законодавство України” за посиланням: https://data.rada.gov.ua/ogd/zak/list.json.
І у отриманих даних виберемо частину інформації, для прикладу - тільки заголовки ('title').

Реалізуємо це через створення функцій:

import requests
import json

URL_4 = 'https://data.rada.gov.ua/ogd/zak/list.json'
# 4.1 Розробка функції для отримання даних із сайту
def get_data(url):
    try:
        response = requests.get(url)
        print('Статус-код:', response.status_code)
        response.raise_for_status()  # Перевірка на помилки HTTP
        data = response.json()
        return data
    except requests.exceptions.RequestException as e:
        print(f"Помилка при отриманні даних: {e}")
        return None
        
# 4.2 Розробка функції для збереження даних у файл
def save_to_file(filename, data):
    try:
        with open(filename, 'w', encoding='utf-8') as f:
            json.dump(data, f, ensure_ascii=False, indent=4)    
        print(f"Дані збережено у файл {filename}")
    except IOError as e:
        print(f"Помилка при збереженні файлу: {e}")
        
# 4.3 Отримання даних та збереження у файл
response = get_data(URL_4)
if response is not None:
    print('Отримані дані:')
    save_to_file('downloaded_data.json', response)
    
# 4.4 Розробка функції для завантаження даних із файлу
def load_from_file(filename):
    try:
        with open(filename, 'r', encoding='utf-8') as f:
            data = json.load(f)
            return data
    except IOError as e:
        print(f"Помилка при читанні файлу: {e}")
        return None
        
# 4.5 Створення об'єкту із даних json-файлу. Виведення заголовків

data = load_from_file('downloaded_data.json')

# Після перегляду файлу можна побачити, 
# що заголовки знаходяться у полі 'title' кожного елемента списку 'item'.
# Тому для виведення заголовків можна використати наступний код:
pprint.pprint([x['title'] for x in data['item']])

Для статичного парсингу, з використанням бібліотеки requests, доцільно задавати заголовки та куки — об'єкт Session. Це дозволяє зберігати стан (наприклад, сесію авторизації) між різними запитами, як у справжньому браузері.

🧩 Приклад
import requests
# 1. Створюємо сесію (вона автоматично зберігатиме куки, які надсилає сервер)
session = requests.Session()
# 2. Налаштовуємо заголовки (Headers)
# Імітуємо реальний браузер Chrome на Windows
custom_headers = {
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36',
    'Accept-Language': 'uk-UA,uk;q=0.9,en-US;q=0.8,en;q=0.7',
    'Referer': 'https://www.google.com/',  # Ніби ми прийшли з пошуку Google
    'Accept': 'text/html,application/xhtml+xml,application/xml;q=0.9,image/avif,image/webp,*/*;q=0.8'
}
# 3. Налаштовуємо початкові куки (наприклад, отримані вручну з браузера)
custom_cookies = {
    'session_id': '123456789abcdef',
    'age_verification': 'true',
    'p_theme': 'dark'
}
# URL ресурсу, який ми хочемо спарсити
url = "https://httpbin.org/headers" # Цей сайт просто повертає ваші заголовки для перевірки
try:
    # 4. Виконуємо запит із передачею заголовків та кук
    response = session.get(
        url, 
        headers=custom_headers, 
        cookies=custom_cookies,
        timeout=10 # Завжди додавайте тайм-аут, щоб скрипт не "завис"
    )
    # Перевірка статусу (200 - OK)
    response.raise_for_status()
    # 5. Вивід результату
    print("Статус-код:", response.status_code)
    print("Вміст відповіді (JSON):")
    print(response.json())
except requests.exceptions.RequestException as e:
    print(f"Помилка під час запиту: {e}")
# Перегляд кук, які сервер міг надіслати нам у відповідь
print("\nКуки в поточній сесії:", session.cookies.get_dict())
🔑 Особливості:**
  • User-Agent: Без нього requests надсилає стандартний заголовок python-requests/2.x.x. Більшість сайтів блокують такі запити миттєво.
  • Referer: Деякі сайти перевіряють, чи перейшли ви за внутрішнім посиланням. Якщо Referer порожній, сервер може розцінити це як бот-активність.
  • Cookies: У закритих групах або кабінетах саме куки (наприклад, session_id або auth_token) є вашою перепусткою. Ви можете скопіювати їх із браузера (F12 -> Application -> Cookies) і вставити в код.

3. Бібліотека playwright

Теорія - 10 хв, практика - 30 хв

Одним із підходів щодо автоматизації діяльності в умовах зазначених обмежень є бібліотека playwright. Яка по суті є програмованим браузером, шо дозволяє імітувати роботу людини (наприклад, натискання посилань, кнопок та інше).

Основне призначення даного модулю є тестування веб-додатків.

Для встановлення застосовується pip

pip install playwright

У подальшому має бути встановлено відповідний браузер для роботи у мережі

playwright install chromium

Слід зазначити, браузер який встановлюється є майже повноцінним застосунком. А тому і час на його завантаження є тривалим.

Зазначені бібліотеки дозволяють здійснювати роботу по перегляду веб-ресурсів

🧩 Приклад
from playwright.sync_api import sync_playwright

url = 'some_url'
with sync_playwright() as p:
	brw = p.chromium.launch(headless=False)
	page = brw.new_page()
	page.goto(url)

Для контролю стану завантажених сторінок застосовується знімок екрану.

page.screenshot('scr01.png', full_page=True)

Як правило, такий знімок буде відображати напівзаповнену сторінку. Для здійснення затримки до повного підвантаження, застосовують відповідні методи

page.wait_for_load_state('networkidle')

Враховуючи наявність оптимізації веб-застосунків, наприклад, завантажувати лише видиму частину, застосовують і інші методи бібліотеки. Нижче наведено команда для прокручування сторінки до низу.

page.eveluate('()=>window.scroll(0, document.body.scrollHeight)')

4. Пакет selectolax для роботи із css-селекторами

Теорія - 10 хв, практика - 40 хв

Для зручної роботи по доступу до інформації, що розміщена у тегах завантаженої html-сторінки, є ряд пакетів та бібліотек (BeautifulSoup, lxml). Серед них доцільно виділити selectolax, яка дозволяє забезпечити гнучкість при створенні запитів та достатньо високу швидкодію.
На офіційному сайті наведено таблицю швидкості роботи даного пакету у порівнянні із схожими за призначенням

У подальшому для роботи із html-документом застосовуються відповідні 'парсери'

from selectolax.parser import HTMLParser
import requests as r

url = ''

resp = r.get(url)
html_doc = resp.text

tree = HTMLParser(html_doc)
print(tree.css('img'))

Для доступу до елементів html-документу можна використовувати метод .css(), що на виході видає список знайдених елементів.

Selectolax повністю покладається на CSS-селектори. Це потужний інструмент, який дозволяє "точково" вибирати елементи без довгих циклів.

2.1. Базові селектори
  • tag — вибір за назвою тегу (напр. p, div, h1).
  • .class — вибір за класом (напр. .main-content).
  • #id — вибір за унікальним ідентифікатором (напр. #login-button).
2.2. Комбінації та ієрархія
  • div p — усі теги p, які знаходяться всередині div (на будь-якій глибині).
  • div > p — тільки ті p, які є прямими нащадками div.
  • div.active — тег div, який має клас active.
  • a, span — вибере всі посилання та всі текстові відрізки (span) одночасно.
  • div + a - вибере сусідній тег a відносно тегу div.
2.3. Робота з атрибутами
  • [attribute] — елементи, що мають такий атрибут (напр. [href]).
  • [attribute=value] — точна відповідність (напр. [target="_blank"]).
  • [attribute*="value"] — містить підрядок (напр. a[href*="python.org"]).
  • [attribute^="value"] — починається з (напр. a[href^="https"]).
2.4. Псевдокласи (корисно для списків)
  • :first-child — перший елемент у батьківському контейнері.
  • :last-child — останній елемент.
  • :nth-child(n) — n-ний елемент (наприклад, :nth-child(2) вибере другий елемент).

Порядок оцінювання

Відповідно до РПНД на даному груповому занятті слухач може отримати максимально 3 бали за 100 бальною шкалою оцінювання даної дисципліни. При цьому,

  • за контрольне опитування - 1.2 балів,
  • за виконання практичних завдань - 1.8 балів.
