2. Основи роботи веб-застосунків

Теорія - 40 хв, практика - 0 хв

🎯Веб-застосунок - програмне забезпечення, яке працює через веб-браузер і виконує певні функції або надає послуги користувачам через інтернет.

На відміну від традиційних програм, які встановлюються на комп’ютер, веб-застосунки доступні онлайн і не потребують встановлення.

Загальний вигляд взаємодії між клієнтом та сервером наступний:

Рис. 2.1

Зі сторони клієнта формується запит на отримання даних від сервера. Структура такого запиту наступна:

  • Метод: GET, POST, PUT, DELETE
  • URL: адреса ресурсу
  • Заголовки (Headers): додаткова інформація (тип контенту, авторизація)
  • Тіло (Body): дані, що передаються (тільки для POST/PUT)
🧩 Приклад POST-запиту
POST /api/login HTTP/1.1
Host: example.com
Content-Type: application/json

{
  "username": "user123",
  "password": "securePass"
}

2.1 Методи запитів

🎯Методи запитів — це команди, які визначають, як клієнт (наприклад, браузер) взаємодіє з сервером. Найпоширеніші — GET, POST, PUT, DELETE.

Ось детальний огляд основних HTTP-методів, які використовуються у веб-застосунках:

Основні HTTP-методи
Метод Призначення
GET Отримання даних з сервера. Не змінює стан ресурсу.
POST Надсилання даних на сервер (наприклад, форма реєстрації).
PUT Оновлення або створення ресурсу на сервері.
DELETE Видалення ресурсу з сервера.
PATCH Часткове оновлення ресурсу.
HEAD Як GET, але повертає лише заголовки без тіла відповіді.
OPTIONS Запитує доступні методи для ресурсу.
CONNECT Створює тунель для безпечного з'єднання (наприклад, HTTPS).
TRACE Повертає запит, який отримав сервер (для діагностики).
🧩 Приклади застосування
GET-запит:
GET /products HTTP/1.1
Host: example.com

Використовується для отримання списку товарів.

POST-запит:
POST /login HTTP/1.1
Host: example.com
Content-Type: application/json

{
  "username": "user123",
  "password": "securePass"
}

Використовується для авторизації користувача.

🔑 Особливості
  • GET — швидкий, кешується, але небезпечний для передачі конфіденційних даних.
  • POST — безпечніший для передачі даних, не кешується.
  • PUT/DELETE — часто використовуються в REST API для управління ресурсами.
  • PATCH — зручний для оновлення окремих полів без перезапису всього ресурсу.

2.2 Заголовки запитів (HTTP Headers)

🎯HTTP-заголовки (headers) — це частина протоколу HTTP, яка передає додаткову інформацію між клієнтом (наприклад, браузером) і сервером.

Заголовки використовуються як у запитах, так і у відповідях, щоб описати властивості повідомлення, керувати кешуванням, автентифікацією, безпекою тощо.

Основні типи заголовків
Заголовок Призначення
Content-Type Вказує тип даних у тілі запиту (наприклад, application/json, text/html)
Authorization Містить токен або облікові дані для доступу до захищених ресурсів
User-Agent Ідентифікує клієнт (браузер, застосунок), який надсилає запит
Accept Вказує, які типи відповідей клієнт готовий прийняти
Host Вказує домен сервера, до якого надсилається запит
Cookie Передає збережені куки для сесії користувача
Cache-Control Керує кешуванням запиту або відповіді
Referer Вказує URL сторінки, з якої прийшов запит
Content-Length Вказує розмір тіла запиту у байтах
Connection Керує типом з'єднання (наприклад, keep-alive)
🔐 Заголовки безпеки

Ці заголовки допомагають захистити веб-додатки:

  • Strict-Transport-Security: примусове використання HTTPS
  • Content-Security-Policy: захист від XSS-атак
  • X-Frame-Options: захист від clickjacking
  • X-Content-Type-Options: заборона MIME-sniffing
Додаткові заголовки
  • X-Requested-With: часто використовується для AJAX-запитів (XMLHttpRequest)
  • Origin: вказує джерело запиту (важливо для CORS)
  • Access-Control-Allow-Origin: відповідає на CORS-запити, дозволяючи доступ з певних доменів
Тип заголовка Опис
Загальні Застосовуються до запитів і відповідей (Connection, Cache-Control)
Заголовки запиту Відправляються клієнтом (User-Agent, Accept, Authorization)
Заголовки відповіді Відправляються сервером (Server, Set-Cookie, Location)
Заголовки сутності Описують тіло повідомлення (Content-Type, Content-Length)
🧩 Приклад HTTP-запиту з заголовками
GET /api/products HTTP/1.1
Host: example.com
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Accept: application/json
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
🧩 Приклад запиту та відповіді

Request:

GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html

Response:

HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 1024
Set-Cookie: sessionId=abc123; HttpOnly

2.4 Взаємодія між клієнтом та сервером

Для ефективної роботи між клієнтом та сервером передбачені механізми, що дозволяють певною мірою зберігати контекст попередньої взаємодії. Одним із таких способів є використання файлів, що називаються cookie.

🎯 Cookie-файл — це невеликий текстовий файл, який веб-сайт зберігає на пристрої користувача через браузер.

Його основна мета — зберігати інформацію про взаємодію користувача з сайтом, щоб забезпечити персоналізований досвід.

🔑 Основні характеристики cookie-файлів:
  • Зберігаються локально на комп’ютері або мобільному пристрої
  • Передаються назад на сервер при кожному запиті до сайту
  • Містять пари "ключ-значення", наприклад: session_id=abc123
Приклади застосування:
Призначення Приклад використання
Аутентифікація Зберігання токена входу в систему
Персоналізація Запам’ятовування мови інтерфейсу чи теми
Аналітика Відстеження поведінки користувача
Кошик покупок Зберігання товарів у кошику
Ретаргетинг реклами Показ реклами на основі попередніх дій
Види cookie-файлів:
  • Сесійні (session cookies) — зберігаються лише під час відкритої сесії браузера
  • Постійні (persistent cookies) — зберігаються на пристрої до певної дати або поки не будуть видалені
  • Сторонні (third-party cookies) — створені іншими доменами (наприклад, рекламними мережами)
🔐 Безпека та конфіденційність

Cookie-файли не можуть самостійно запускати код або передавати віруси, але можуть бути використані для відстеження активності. Тому сучасні браузери та закони (наприклад, GDPR) вимагають згоди користувача на їх використання.

2.5 Завантаження веб-ресурсів. Бібліотека request

Теорія - 20 хв, практика - 0 хв

Для роботи із http-запитами у python є влаштовані та написані окремо бібліотеки. Як правило для роботи із запитами застосовують бібліотеку requests

🎯requests — це бібліотека Python для роботи з HTTP-запитами. Дозволяє надсилати запити до веб-серверів, отримувати відповіді, працювати з різними форматами даних (HTML, JSON тощо), змінювати заголовки, надсилати файли та багато іншого.

Для встановлення бібліотеки необхідно скористатися пакетним менеджером

pip install requests
🔑 Основні можливості:
  • Надсилання GET, POST, PUT, DELETE та інших HTTP-запитів
  • Робота з параметрами URL та формами
  • Зміна HTTP-заголовків
  • Підтримка cookies та сесій
  • Просте отримання та збереження файлів
  • Зручна робота з JSON-даними
Переваги застосування бібліотеки requests
  • Простий синтаксис
  • Документованість та велика спільнота
  • Підтримка сучасних стандартів HTTP
    Отримання тексту веб-сторінки
🧩 Приклад
import requests
url = 'https://httpbin.org/html'
response = requests.get(url)
print('Статус-код:', response.status_code)
print('Перші 500 символів HTML:')
print(response.text[:500])

Редагування заголовків запиту

🧩 Приклад
headers = {
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) CustomBot/1.0',
    'Accept-Language': 'uk'
}
url = 'https://httpbin.org/headers'
response = requests.get(url, headers=headers)
print('Відповідь сервера:')
print(response.json())

Для отримання файлів у форматі json достатньо застосувати наступний код

3. Загальні відомості про структуру веб-документу

Теорія - 25 хв, практика - 0 хв

Сторінка, яка відображається у веб-браузері є поєднанням html-тегів, правил їх відображення (СSS). Для забезпечення взаємодії із користувачем може використовуватися мова програмування JavaScript.

🎯HTML-сторінка — це документ, створений мовою розмітки HTML (HyperText Markup Language), який веб-браузер інтерпретує та відображає як веб-сторінку.

🎯 CSS (Cascading Style Sheets) — це мова стилів, яка використовується для опису зовнішнього вигляду HTML-сторінок. Вона дозволяє відокремити структуру (HTML) від оформлення (CSS), роблячи веб-розробку більш гнучкою та зручною.

🔑 Основні можливості CSS:
  • Кольори та шрифти: задають палітру, типи та розміри шрифтів.
  • Розташування елементів: керують відступами, вирівнюванням, позиціонуванням.
  • Фон та зображення: додають фонові кольори, градієнти, картинки.
  • Анімації та переходи: створюють динамічні ефекти.
  • Адаптивність: дозволяють сторінці виглядати добре на різних пристроях (телефон, планшет, комп’ютер).
🧩 Приклад
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <title>CSS приклад</title>
  <style>
    body {
      background-color: #f0f0f0;
      font-family: Arial, sans-serif;
    }
    h1 {
      color: darkblue;
      text-align: center;
    }
    p {
      color: #333;
      font-size: 18px;
    }
  </style>
</head>
<body>
  <h1>Привіт, CSS!</h1>
  <p>Цей текст стилізований за допомогою CSS.</p>
</body>
</html>
📌 Пояснення:
  • background-color — задає колір фону.
  • font-family — визначає шрифт.
  • color — колір тексту.
  • text-align — вирівнювання тексту.

Слід зазначити, що html-документ має вкладену структуру, зовнішній парний тег <html></html> містить у собі інші теги, які вкладаються один у одного. Теги можуть містити інформацію - текстову чи графічну, або бути контейнерами для інших тегів.

3.1 Атрибути HTML-тегів

Для забезпечення можливості більш гнучкого налаштування HTML-сторінки, а саме що стосується тегів - HTML-елемент, передбачено можливість використання атрибутів. Їх призначення може бути різним.

🎯 Атрибути — це спеціальні слова, які надають додаткову інформацію про HTML-елемент або змінюють його поведінку. Якщо тег — це "іменник" (наприклад, картинка чи посилання), то атрибут — це "прикметник" (яка саме картинка, куди веде посилання).

🔑 Основні правила написання:
  1. Атрибути завжди додаються у відкриваючий тег.
  2. Зазвичай вони складаються з пари назва="значення".
  3. Значення атрибута рекомендується брати у подвійні лапки.

Синтаксис виглядає так:
<тег назва_атрибута="значення">Контент</тег>

🧩 Приклад:

<a href="https://google.com">Перейти в Google</a>

  • <a> — тег посилання.
  • href — назва атрибута (hyperlink reference).
  • "https://google.com" — значення (куди саме вести користувача).

3.2 Класифікація атрибутів

Всі атрибути можна розділити на три великі групи:

📌 Глобальні атрибути

Ці атрибути можна застосовувати майже до будь-якого HTML-елемента.

Атрибут Опис Приклад
id Унікальний ідентифікатор елемента на сторінці. <div id="header">
class Назва класу (використовується для стилізації в CSS). <p class="text-bold">
style Дозволяє писати CSS-код прямо в тегу. <h1 style="color: red;">
title Спливаюча підказка при наведенні мишкою. <span title="Додаткова інфо">
lang Визначає мову контенту. <html lang="uk">
📌 Специфічні атрибути

Вони працюють тільки з конкретними тегами.

  • Для зображень (<img>):
  • src — шлях до файлу.
  • alt — альтернативний текст (якщо картинка не завантажилась).
  • Для посилань (<a>):
  • href — адреса посилання.
  • target="_blank" — відкриває посилання у новій вкладці.
  • Для форм (<input>):
  • type — визначає вид поля (text, password, checkbox).
  • placeholder — підказка всередині поля.
📌 Булеві (логічні) атрибути

Ці атрибути не потребують значення. Якщо вони присутні — властивість увімкнена.

  • disabled — робить кнопку чи поле неактивним.
  • required — робить поле обов'язковим для заповнення.
  • checked — для вибраних чекбоксів.
🔑 Поради та кращі практики
  1. Малі літери: Хоча HTML не чутливий до регістру, за стандартом назви атрибутів завжди пишуться маленькими літерами (href, а не HREF).
  2. Лапки: Завжди використовуйте лапки для значень, навіть якщо вони складаються з одного слова. Це допоможе уникнути помилок у майбутньому.
  3. Доступність (Accessibility): Ніколи не забувайте про атрибут alt для зображень — це критично важливо для людей з порушенням зору, які використовують скрінрідери.
Атрибути id мають бути унікальними! Не можна використовувати однаковий id для двох різних елементів на одній сторінці. Для групування елементів використовуйте class.
